## 开发节奏与约定

1. **每阶段结束必须编译 + 测试通过**，再进入下一阶段。
2. **需要部署的中间件（Nacos / PostgreSQL / MySQL / Sentinel / Seata / Redis）直接写进 `docker-compose.yml` 并请你启动**，绝不写模拟桩 / Embedded 假实现替代真实链路。
3. **每完成一步**：更新本文件阶段状态 + 在 `开发日志.md` 追加一条（做了什么 / 踩的坑 / 验证结果）。
4. 数据库主基调 **PostgreSQL（主）**，引入 **MySQL（第二数据源）** 做多数据源演示。
5. 基础模块就绪后，**优先**落地 **熔断限流（Sentinel）** 与 **分布式事务（Seata）**。

## 各阶段详情

### P0 · 骨架
- **目标**：可解析依赖、可 install 的空壳工程。
- **涉及**：父 `pom.xml`（已为 SCA BOM 空壳）、`docker-compose.yml` 加入 Nacos / PostgreSQL / MySQL / Redis。
- **关键动作**：定义各模块 `pom` 与目录；common 层为 `jar` 库，业务服务为 `boot` 可执行 jar。
- **需部署**：Nacos、PostgreSQL、MySQL、Redis（写进 compose，请你 `docker compose up -d`）。
- **交付标准**：`mvn -pl <模块> -am install` 通过。

### P1 · 公共基础 + 数据层（最基础模块）
- **目标**：日志、多数据源、一个能跑的简单接口。
- **涉及**：`common-core`（R / BizException / 常量）、`common-log`（traceId / 访问日志切面）、`common-web`（全局异常 / 跨域 / 响应包装）、`common`（多数据源自动配置：dynamic-datasource，默认 `pg`，第二数据源 `mysql`）、`ms-user`（PG 上用户 CRUD 接口）。
- **关键动作**：
  - `common-log`：MDC `traceId` 工具 + `AccessLogAspect`。
  - 多数据源：每个业务服务配 `spring.datasource.dynamic` 主 `pg` / 副 `mysql`；演示 `@DS("mysql")` 在部分表切换。
  - `ms-user`：`UserController` → `UserService` → `UserMapper`（MyBatis-Plus），PG 建表。
- **需部署**：PostgreSQL、MySQL（已随 P0 起）。
- **交付标准**：`curl /user/{id}` 经 PG 返回；日志带 traceId；@DS 切 MySQL 的接口可验证。

### P2 · 熔断限流（Sentinel）【优先】
- **目标**：网关与 Feign 调用具备流控 / 熔断 / 降级能力。
- **涉及**：`ms-gateway`（Sentinel 网关流控）、`common-feign`（Feign 熔断降级兜底）、`ms-order`（Feign 调 user 加降级）。
- **关键动作**：
  - 网关路由接 `SentinelGatewayFilter` + 限流规则（QPS / 线程数）。
  - Feign 调用接 Sentinel 熔断（慢调用比例 / 异常比例），异常时走 `Fallback` 返回友好 `R`。
  - 演示：压测 / 手动触发降级，观察兜底生效、链路不雪崩。
- **需部署**：Sentinel Dashboard（写进 compose，请你启动；规则可控制台下发或代码初始化）。
- **交付标准**：限流返回 429 / 降级返回约定 `R`；Dashboard 可见实时 QPS 与熔断状态。

### P3 · 分布式事务（Seata）【优先】
- **目标**：跨服务写操作具备原子性（订单创建 + 用户侧变更要么全成要么全回）。
- **涉及**：`ms-order`、`ms-user`、Seata Server、各库 `undo_log` 表。
- **关键动作**：
  - 引入 `seata-spring-boot-starter`；`ms-order` 的创建接口加 `@GlobalTransactional`。
  - 演示：order 写 PG、user 侧写（可跨 PG/MySQL 演示多数据源 + 分布式事务）被同一全局事务管理；人为抛错触发全局回滚，验证数据一致。
  - 另演示「最终一致性」思路（本地消息表 / 事务消息）作为对比教学。
- **需部署**：Seata Server（写进 compose，请你启动；注册到 Nacos）。
- **交付标准**：异常场景下两库数据均回滚，无脏写；正常场景两库均提交。

### P4 · 安全认证
- **目标**：统一登录签发 JWT + 网关集中鉴权 + 方法级权限。
- **涉及**：`common-security`、`ms-auth`、`ms-gateway`（`AuthFilter`）。
- **关键动作**：`ms-auth` 登录签发 `accessToken`+`refreshToken`（Redis）；网关校验 JWT 白名单放行；下游还原 `LoginUser` + `@RequiresPermission`。
- **需部署**：Redis（已起）。
- **交付标准**：无 token 被拦、带合法 JWT 放行、越权返回 403。

### P5 · 调用增强与可观测补全
- **目标**：Feign 透传完善、访问日志、可选 SkyWalking 链路可视化。
- **涉及**：`common-feign`（透传 + 降级落地）、`common-log`（访问日志脱敏）、可选 SkyWalking Agent。
- **交付标准**：跨进程 traceId 连续；SkyWalking 可见调用拓扑（可选）。

### P6 · 进阶
- **目标**：Nacos Config 多环境（namespace dev/test/prod）+ 动态刷新。
- **涉及**：各服务 `bootstrap.yml` 接 Nacos Config。
- **交付标准**：改 Nacos 配置热更生效，无需重启。
