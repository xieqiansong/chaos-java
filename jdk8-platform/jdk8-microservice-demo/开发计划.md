# 开发计划 · jdk8-microservice-demo

> 本文件是**分阶段开发路线图**，从 `README.md` 拆分而来。每完成一步，在此更新阶段状态，并在 `开发日志.md` 追加记录。

---

## 开发节奏与约定

1. **每阶段结束必须编译 + 测试通过**，再进入下一阶段。
2. **需要部署的中间件（Nacos / PostgreSQL / MySQL / Sentinel / Seata / Redis）直接写进 `docker-compose.yml` 并请你启动**，绝不写模拟桩 / Embedded 假实现替代真实链路。
3. **每完成一步**：更新本文件阶段状态 + 在 `开发日志.md` 追加一条（做了什么 / 踩的坑 / 验证结果）。
4. 数据库主基调 **PostgreSQL（主）**，引入 **MySQL（第二数据源）** 做多数据源演示。
5. 基础模块就绪后，**优先**落地 **熔断限流（Sentinel）** 与 **分布式事务（Seata）**。

## 各阶段详情

### P0 · 骨架
- **目标**：可解析依赖、可 install 的空壳工程。
- **涉及**：父 `pom.xml`（已为 SCA BOM 空壳）、`docker-compose.yml` 加入 Nacos / PostgreSQL / MySQL / Redis。
- **关键动作**：定义各模块 `pom` 与目录；common 层为 `jar` 库，业务服务为 `boot` 可执行 jar。
- **需部署**：Nacos、PostgreSQL、MySQL、Redis（写进 compose，请你 `docker compose up -d`）。
- **交付标准**：`mvn -pl <模块> -am install` 通过。

### P1 · 公共基础 + 数据层（最基础模块）【已完成】
- **目标**：日志、多数据源、一个能跑的简单接口。
- **实际交付**：
  - `common-core`：`R<T>` 统一响应体、`ResultCode` 错误码枚举、`BizException` 业务异常、`BaseEntity` 审计基类（createdAt/updatedAt/deleted）、`DataSourceConstants`（pg/mysql 命名常量）。
  - `common-log`：MDC `TraceIdFilter`（网关入口生成/透传 traceId，Servlet 环境）+ `logback-spring.xml` 统一格式（`%X{traceId}` 串日志）。访问日志切面 deferred 到 P5。
  - `common-web`：`GlobalExceptionHandler`（BizException/校验失败/兜底 500 → `R`）、`ResponseAdvice`（领域对象自动包成 `R`）。
  - 多数据源：`ms-user` 用 dynamic-datasource 配主 `pg` / 副 `mysql`；`User` 走 PG，`UserTag` 用 `@DS("mysql")` 切到 MySQL，证明同应用内按注解切异构库。
  - `ms-user`：`UserController` → `UserService`/`UserTagService` → `UserMapper`/`UserTagMapper`（MyBatis-Plus，逻辑删除 + 自动填充时间）。
  - DDL：`sql/demo_ms_pg_ddl.sql`（PG）、`sql/demo_ms_mysql_ddl.sql`（MySQL）。
- **测试**：`RTest`（3 例，契约）、`UserControllerTest`（2 例，@WebMvcTest 切片 + Mapper 桩，验证统一响应/异常处理）、`SqlSliceTest`（1 例，H2 离线模拟双库，断言 @DS 路由隔离）。
- **需部署**：PostgreSQL、MySQL（你本机已起；DDL 建库后即可）。
- **交付标准**：编译+全测试通过；`curl /users`、`/users/{id}` 走 PG、`/users/{id}/tags` 走 MySQL；日志带 traceId。

### P2 · 熔断限流（Sentinel）【已完成】
- **目标**：网关与 Feign 调用具备流控 / 熔断 / 降级能力。
- **涉及**：`ms-gateway`（Sentinel 网关流控）、`common-feign`（Feign 熔断降级兜底）、`ms-order`（Feign 调 user 加降级）。
- **关键动作**：
  - 网关路由接 `SentinelGatewayFilter` + 限流规则（QPS / 线程数）。
  - Feign 调用接 Sentinel 熔断（慢调用比例 / 异常比例），异常时走 `Fallback` 返回友好 `R`。
  - 演示：压测 / 手动触发降级，观察兜底生效、链路不雪崩。
- **需部署**：Sentinel Dashboard（写进 compose，请你启动；规则可控制台下发或代码初始化）。
- **交付标准**：限流返回 429 / 降级返回约定 `R`；Dashboard 可见实时 QPS 与熔断状态。

### P3 · 分布式事务（Seata）【已完成】
- **目标**：跨服务写操作具备原子性（创建订单 + 扣减账户余额要么全成要么全回）。
- **涉及**：`ms-order`、`ms-user`、Seata Server 1.6.1、两库 `undo_log` 表。
- **关键动作 / 实际交付**：
  - 注册中心用 **file 模式**（`registry.conf` + `file.conf`，置于 `common-core` 供两端复用），免 Nacos；事务分组 `my_test_tx_group`，TC 地址 `localhost:8091`。
  - `ms-order`（单数据源 MySQL）：`Order` 改为 MyBatis-Plus 实体（写 `t_order`），`OrderService.createWithTx` 加 `@GlobalTransactional`——先写订单分支、再经 OpenFeign 调 user 扣账户；`enable-auto-data-source-proxy=true` 由 Seata 自动代理数据源。
  - `ms-user`（多数据源 PG/MySQL）：新增 `Account` 实体（写 PG `t_account`）+ `AccountService.deduct`；`spring.datasource.dynamic.seata=true` 走 dynamic-datasource 原生 Seata 集成（故关闭 Seata 自动代理），xid 经 Feign 自动透传，扣减自动成为同一全局事务的分支。
  - 余额不足/账户异常时 user 返回 409 `BALANCE_NOT_ENOUGH`，order 侧据此抛异常 → 订单与账户两库按 `undo_log` 一起回滚；正常场景两库均提交。两种数据源接入姿势（dynamic 原生 / 自动代理）都演示到。
  - `docker-compose.yml` 增加 Seata Server（1.6.1，file 注册，`seata/` 内置 `registry.conf`/`file.conf` 覆盖），端口 8091。
- **测试**：`AccountServiceImplTest`（3 例，mock Mapper 验证余额不足/账户不存在抛异常）、`OrderSeataRollbackTest`（2 例，mock Feign+Mapper 验证扣减失败触发回滚路径）；离线 CI 全绿。
- **需部署**：Seata Server（`docker compose up -d` 起；注册中心 file 模式无需 Nacos）。
- **交付标准**：异常场景下订单与账户两库均回滚、无脏写；正常场景两库均提交；日志可见全局事务 xid（TX_XID）。

### P4 · 安全认证【已完成】
- **目标**：统一登录签发 JWT + 网关集中鉴权 + 方法级权限。
- **涉及**：`common-security`、`ms-auth`、`ms-gateway`（`AuthGlobalFilter`）、`ms-user`/`ms-order`（接入 `@RequiresPermission`）。
- **关键动作**：
  - `ms-auth` 登录签发**双令牌**：`accessToken`（HS256 无状态、30min）+ `refreshToken`（存 Redis、7d、可吊销）；刷新/登出演示吊销能力。
  - `common-security` 提供 `JwtProvider`（网关与下游共用同一密钥本地验签）、`LoginUser` 上下文、`@RequiresPermission` 注解 + `PermissionInterceptor`。
  - `ms-gateway` 用 `AuthGlobalFilter` 对白名单（`/auth/**` 等）放行，其余无 token/非法 → 401 短路；合法则透传 `Authorization` 下游。
  - `ms-user`/`ms-order` 用 `@RequiresPermission("user:read"/"user:write"/"order:read"/"order:write")` 做方法级细粒度授权，`GET /users/me`、`GET /orders/me` 还原当前登录身份。
- **需部署**：Redis（已起；无 Redis 可设 `REFRESH_STORE=memory` 走内存兜底）。
- **交付标准**：无 token 被拦、带合法 JWT 放行、越权返回 403、refresh 吊销后不可再用。
- **验证**：`mvn -o install` 全绿（新增 `JwtProviderTest`/`AuthDecisionTest`/`AuthServiceImplTest`/`UserControllerTest` 权限用例/`PermissionInterceptorOrderTest`）。

### P5 · 调用增强与可观测补全【已完成】
- **目标**：Feign 透传完善、访问日志、可选 SkyWalking 链路可视化。
- **涉及**：`common-feign`（透传 + 降级落地）、`common-log`（访问日志脱敏）、可选 SkyWalking Agent。
- **关键动作 / 实际交付**：
  - **Feign 透传完善**：`TraceFeignInterceptor` 在已有 `traceId` + `Authorization` 透传基础上，新增调用方身份头 `X-User-Id`/`X-User-Name`（取自 MDC，由 `PermissionInterceptor` 在还原登录用户后写入）；身份头仅作上下文/日志用途，下游鉴权仍以 JWT 为准——演示「透传 vs 重新解析」两种思路的边界。
  - **访问日志（common-log）**：新增 `AccessLogAspect`（`@Around` 所有 `@RestController`，零侵入打印 `方法 / 脱敏入参 / 耗时 / 成败 / traceId` 到独立 logger `ACCESS_LOG`），配 `SensitiveMasker` 脱敏工具（按字段名 password/token/secret… 或 `@Sensitive` 注解打码，递归处理 Map/POJO/Collection/数组，对 Servlet/Spring 框架对象输出类型占位）。`LoginRequest.password` 标注 `@Sensitive` 作为样例。`logging.access.enabled`/`include-args` 可开关。
  - **可观测链路连续性**：网关 → user → order 全程 `X-Trace-Id` 连续（MDC + Feign 透传 + 下游续接），访问日志均带 traceId，跨进程可串联。
  - **可选 SkyWalking**：`docker-compose.yml` 追加注释段 `skywalking-oap`/`skywalking-ui`（OAP 用 h2 零外部依赖），默认不随 `up` 启动；README 写明启用方式与 agent 接入。项目本身不依赖 SkyWalking 即可演示链路。
- **测试**：`TraceFeignInterceptorTest`（3 例：身份透传 / MDC 降级 / 无 Authorization 不串身份）、`SensitiveMaskerTest`（6 例：Map/注解/嵌套/集合/基础类型/超长截断）、`AccessLogAspectTest`（4 例：格式化/成功脱敏/失败重抛/关闭入参），离线全绿。
- **需部署**：无（可观测补全均不依赖外部中间件；SkyWalking 仅可选项）。
- **交付标准**：跨进程 traceId 连续；访问日志可观察且密码/token 不落盘；SkyWalking 可见调用拓扑（启用后）。

- **交付标准**：改 Nacos 配置热更生效，无需重启。
