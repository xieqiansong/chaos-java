## [2026-07-24] 阶段 P4：安全认证（JWT + 网关集中鉴权 + 方法级权限，完成）

- **做了什么**
  - `common-security`（落地）：`JwtProvider`（jjwt 0.11.x，HS256，签发/校验 access+refresh，claim 含 uid/uname/perms/typ/jti，密钥与网关共享）、`JwtProperties`（`ms.security.jwt.*`）、`SecurityConstants`（头名/前缀/白名单/claim 键）、`LoginUser` + `LoginUserContext`（ThreadLocal）、`@RequiresPermission` + `Logical` 注解、`PermissionInterceptor`（Servlet，解析 token→设上下文→校验注解权限，401/403 直接写 R 形状 JSON）、`JwtAutoConfig`（提供 `JwtProvider` 与 Servlet 下的 `PermissionInterceptor`）。`spring-webmvc`/`javax.servlet-api` 用 `provided` 作用域，避免传递进 WebFlux 网关。
  - `ms-auth`（落地）：登录签发**双令牌**（access 30min 无状态 + refresh 7d 存 Redis），`RefreshTokenStore` 接口两实现——`RedisRefreshTokenStore`（默认，可吊销、登出删前缀 key 踢下线）与 `InMemoryRefreshTokenStore`（设 `REFRESH_STORE=memory` 兜底，无 Redis 也能跑）；`UserStore` 内存样例账号 `admin/admin123`（全权限）、`guest/guest123`（只读）；`AuthController` 暴露 `/auth/login`、`/auth/refresh`、`/auth/logout`，均在网关白名单内。
  - `ms-gateway`（落地）：`AuthDecision`（纯逻辑：白名单判定 + token 合法性判定，可单测）+ `AuthGlobalFilter`（WebFlux GlobalFilter，顺序早于 Sentinel，无 token/非法且非白名单→401 短路，合法则透传 `Authorization`）；新增 `ms-auth-route` 路由 `lb://ms-auth`；依赖 `common-security` 复用 `JwtProvider` 本地验签。
  - `ms-user`/`ms-order`（接入）：各加 `common-security` 依赖；`UserController` 加 `GET /users/me`（`user:read`）、`DELETE /users/{id}`（`user:write`）演示细粒度授权；`OrderController` 给 `POST`/`POST /tx`（`order:write`）、`GET /{id}`/`GET /me`（`order:read`）加注解。`TraceFeignInterceptor` 已天然透传 `Authorization`，使 Feign 跨服务调用沿用调用方 token。
  - `application-common.yml`：修正 Redis 占位（端口 30102→6379、密码与 docker-compose 的 `redis123` 对齐）。
- **关键决策 / 教学点**
  - **双令牌 + 可吊销 refresh**：access 无状态享 JWT 红利，refresh 存服务端补「主动登出」短板；access 过期前若 refresh 被吊销则必须重登。
  - **网关集中鉴权 + 下游细粒度授权分层**：网关只验「是否合法登录」，下游用 `@RequiresPermission` 做「是否有权限」，职责清晰；access/refresh 类型隔离（claim `typ`）防越权复用。
  - **common-security 跨 WebFlux/Servlet 共存**：`JwtProvider`/`JwtProperties` 不依赖 servlet，`PermissionInterceptor`/`SecurityWebConfig` 用 `@ConditionalOnWebApplication(SERVLET)` 仅在下游加载，避免与网关 WebFlux 冲突。
- **踩的坑**
  1. `PermissionInterceptor` 的 JSON 转义串多写了一个引号导致编译失败；改写为 char 循环 `escape` 消除歧义。
  2. `spring-webmvc` 以 `provided` 引入时不会把 `javax.servlet-api` 透传进编译期，common-security 编译报找不到 `javax.servlet.http`；显式补 `javax.servlet-api`（同样 `provided`）解决。
  3. `SecurityWebConfig` 构造器依赖自身 `@Bean` 的 `PermissionInterceptor` 形成循环引用；把该 `@Bean` 上移到 `JwtAutoConfig`（用 `@ConditionalOnWebApplication(SERVLET)` 限定），`SecurityWebConfig` 改为注入，破环。
  4. `RefreshTokenStore` 的条件原用 `@ConditionalOnBean(RedisConnectionFactory)`，存在与 `RedisAutoConfiguration` 的注册顺序坑；改为纯 `@ConditionalOnProperty`（`ms.security.refresh-store`）驱动，规避顺序陷阱。
- **验证结果**：`mvn -o install` 全模块 **BUILD SUCCESS**；新增 `JwtProviderTest`×5（签发往返/过期/篡改/refresh jti/错密钥）、`AuthDecisionTest`×5（白名单/合法 access/缺头·前缀错·用 refresh·过期）、`AuthServiceImplTest`×5（登录成功/失败/刷新成功/登出后刷新失效/用 access 刷新被拒）、`UserControllerTest` 权限用例×4（无 token→401、admin→200、guest 删→403、admin 删→200）+ 原有用例全绿、`PermissionInterceptorOrderTest`×5（订单端无 token/guest/admin/me 权限判定）；离线 CI 全绿。
- **给你的衔接点**：`docker compose up -d` 起 Nacos/Redis/PG/MySQL/Seata（auth 用 Redis 存 refresh；无 Redis 可 `REFRESH_STORE=memory`）。按序启动 Nacos → user(8081) → order(8082) → auth(8083) → gateway(8080)。验证链路：`POST /auth/login?username=admin&password=admin123` 拿 `accessToken`；带 `Authorization: Bearer <accessToken>` 访问 `GET /users/me`（返回 admin 身份）、`POST /orders/tx?userId=1&amount=9.90`（admin 有 order:write 才放行，guest 返回 403）；不带 token 访问受保护接口网关直接 401。

- **关键决策 / 教学点**
  - **身份透传 vs 重新解析**：Feign 调用下游时既透传 `Authorization`（下游仍按 JWT 重新鉴权，权威来源），又附 `X-User-Id`/`X-User-Name`（仅上下文/日志用，降低下游取身份的解析成本）。两路职责清晰，身份头绝不作为放行依据，避免「伪造身份头绕过鉴权」的反模式。
  - **访问日志零侵入 + 脱敏安全**：用 AOP 统一打印，业务方法不加一行日志；脱敏在切面收敛到 `SensitiveMasker` 一处，新增敏感字段只需打 `@Sensitive` 或命中名字约定，杜绝「日志里明文密码」这类安全事故。
  - **可观测不绑定外部系统**：traceId + 访问日志即可演示跨进程链路连续，SkyWalking 仅作「拓扑可视化」可选项，不引入即跑。
- **踩的坑**：无阻断性报错。注意点：AOP 切面需 `proxyTargetClass=true` 才能织入 `@RestController` 这类具体类（默认 JDK 动态代理只代理接口）；`common-feign` 引 `common-security` 需其 `provided` 作用域的 servlet/webmvc 仍对编译期可见（feign 已具备，无冲突）。
- **验证结果**：`mvn -o install` 全模块 **BUILD SUCCESS**；新增 `TraceFeignInterceptorTest`×3（身份透传 / 无 Request 时 MDC 降级 / 无 Authorization 不串身份）、`SensitiveMaskerTest`×6（Map/注解/嵌套/集合/基础类型/超长截断）、`AccessLogAspectTest`×4（格式化/成功脱敏/失败重抛/关闭入参）+ 原有测试全绿，离线 CI 全绿。
- **给你的衔接点**：启动后访问任意 `@RestController` 端点（如 `POST /auth/login`、`GET /users/me`）即可在日志看到 `[ACCESS] trace=... 方法 args=...{password=******}... elapsed=..ms OK`，密码/token 不会落盘。可选 SkyWalking：`docker compose up -d skywalking-oap skywalking-ui` 并给业务服务加 `-javaagent`（见 README）后，访问拓扑可见。
