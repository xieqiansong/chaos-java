# 秒杀系统 Demo - 开发计划

> **参考文档**: [设计一个支持万人同时抢购商品的秒杀系统，如何解决超卖、库存扣减和高并发请求问题？](./设计一个支持万人同时抢购商品的秒杀系统，如何解决超卖、库存扣.md)
>
> **技术栈**: Spring Boot 2.7.18 + JPA + PostgreSQL + Redis(Lettuce) + Redisson + Caffeine + Kafka
>
> **目标**: 实现一个支持万人并发抢购的秒杀系统Demo，解决超卖、库存扣减和高并发问题

---

## 一、技术架构

```
用户请求 → 流量接入层(限流/削峰) → 无状态服务层 → 异步订单队列 → 库存与订单DB
                ↓                           ↓
          缓存层(Redis)              消息队列(Kafka)
```

| 层级 | 技术选型 | 职责 |
|------|----------|------|
| **流量接入层** | Spring Boot Interceptor + Redis令牌桶限流 | 限流削峰，防刷 |
| **缓存层** | Caffeine本地缓存 + Redis | 商品信息本地缓存，库存Redis预扣 |
| **服务层** | Spring Boot Service | 秒杀核心业务逻辑 |
| **异步队列层** | Kafka / 内存队列(模拟) | 异步订单落库，解耦 |
| **数据层** | PostgreSQL + JPA | 订单与库存持久化 |

### 核心组件

- Redis Lua脚本原子扣减库存
- Redis分桶库存策略
- 令牌桶限流算法
- 订单去重(Redis Set)
- 最终一致性(异步对账)

## 四、Redis Key 设计

| Key | 类型 | 说明 |
|-----|------|------|
| `seckill:stock:{productId}` | String | 商品总库存余量 |
| `seckill:stock_bucket:{productId}:{bucketIndex}` | String | 第 N 个库存桶的余量 |
| `seckill:sold_out:{productId}` | String | 1=已售罄，快速过滤 |
| `seckill:order_token:{productId}` | Set | 已处理的令牌集合(防重复提交) |
| `seckill:user_bought:{productId}:{userId}` | String | 用户是否已购买(限购1件) |
| `seckill:rate_limit:{productId}` | String | 令牌桶当前令牌数 |

**请求**:
```json

  "userId": "user123",
  "quantity": 1

```

## 七、核心流程

### 秒杀流程

```
用户请求 → SeckillController
    ↓
① 参数校验
    ↓
② RateLimitInterceptor — 令牌桶限流 (超限返回 429)
    ↓
③ 检查商品是否售罄 (Redis 售罄标记)
    ↓
④ 检查用户是否已购买 (Redis Set，每人限购1件)
    ↓
⑤ Redis Lua 原子扣减库存 — 执行 stock_bucket.lua 遍历分桶
    ↓
⑥ 生成唯一令牌 (UUID/Snowflake)，记录到 Redis Set
    ↓
⑦ 异步发送订单消息 (Kafka / Spring Event)
    ↓
⑧ 返回秒杀成功 + Token
```

### 库存一致性对账

```
① 定时任务扫描所有活跃商品
    ↓
② 汇总 Redis 各分桶余量
    ↓
③ 查询 DB 实际库存 (已售订单数)
    ↓
④ 若不一致，以 DB 为准修正 Redis
```

## 八、防超卖关键设计

| 机制 | 层级 | 说明 |
|------|------|------|
| **Redis Lua 原子扣减** | 缓存层 | 单线程执行Lua，确保判断库存>0和扣减的原子性 |
| **分桶库存** | 缓存层 | 库存分散到N个桶，降低单Key热点竞争 |
| **数据库乐观锁** | 数据层 | `UPDATE stock SET count=count-1 WHERE id=? AND count>0` |
| **订单去重** | 服务层 | Redis Set + 令牌机制，防止重复下单 |
| **最终一致性对账** | 定时任务 | 定期对比Redis与DB库存差异，自动修复 |
